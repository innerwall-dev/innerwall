## What this is

This is the backend gap M3.7's Task 0 found (E1), as its own PR ahead of the console work. The ruling accepted the recommendation. The simulation review's rows, matrix, and recency ordering are keyed by **peer × service**, with the number of workloads in scope that saw each pair. None of the four groupings has that key. Assembling it from them would be client-side aggregation, which ADR-0007 as amended rules out; the per-service fan-out alternative was rejected on the same ground.

ADR-0019 decision 4(b) already names this shape: "grouped by resolved peer and service … with the distinct workload count". The store served it to the command line only (`RollupFlowWindows`). This PR puts it into the operator surface's closed set.

## Change

- **Statement.** `RollupFlowsByPeerService` in `internal/store/queries/flows.sql` has the same filter convention, order, bound, covered range, and window-aggregate totals as its four siblings, plus `count(DISTINCT workload_id)`. Like `rule,peer` and `src,dst`, the peer's label snapshot is the one stored with its most recently seen record. `internal/store/db` is regenerated with the pinned sqlc v1.31.1. No schema or index change.
- **flowstore.** `GroupByPeerService = "peer,service"` joins `GroupBys`, and `Group.WorkloadCount` holds the count. It is zero for every other grouping.
- **readmodel.** The `peer,service` case sets `Keys.Peer`, `Keys.Service`, and `RollupGroup.WorkloadCount`. That field is a pointer, set only by this grouping.
- **API.** `GET /flows/rollup?group_by=peer,service` returns `workload_count` on each group, with `omitempty` on the pointer. No other grouping emits it, because their keys already name at most one workload. The handler is unchanged: the grouping is parsed from the closed set as before.
- **Command line.** `innerwall flows rollup --group-by peer,service` adds a WORKLOADS column, and the usage string lists the fifth grouping. The header now comes from the parsed grouping, not the raw flag, so `--group-by "peer, service"` prints cleanly.
- **Spec and types.** `api/openapi.yaml` gains the enum member and the `workload_count` property. `ui/src/api/generated.ts` is regenerated: two lines, sanctioned fallout. No console fixture or screen is touched.
- **Docs.**
  - ADR-0019 decision 4's body now counts five groupings.
  - A dated amendment note is added: additive detail, and the core decision stands.
  - `ARCHITECTURE.md` and the deploy guide's endpoint table name the grouping and its field.
