Evidence gaps (intervals in which an agent knows its evidence is incomplete) now travel the whole path:
- the agent records them and ships them on `ReportFlows`;
- the control plane stores them;
- a separate read serves them;

## Contract (ADR-0015, amended 2026-10-04)

`ReportFlowsRequest.gaps` is a repeated `EvidenceGap {kind, source, from, to, optional count}`:
- **kind**: `SOURCE_OVERRUN`, `SOURCE_RESTART`, `BUFFER_OVERFLOW`, or `DUMP_TRUNCATED`.
- **source**: `CONNTRACK` or `NFLOG`. It is `UNSPECIFIED` for a buffer overflow, because that loss isn't one source's. This is the one place the shape goes beyond `source: conntrack | nflog`.
- **count**: present only where it is known (buffer overflow, truncated dump).

Gaps ride the next window, and a window may carry gaps with no records. `Heartbeat.source_overruns` is the additive overrun counter. `FlowRecord.connection_count` now documents "opened, or found live at subscription, in the window", which PR A deferred here. `buf breaking` against `main` is clean.

## Agent

- **Buffer drops become gaps.** The buffer records each drop as a `buffer_overflow` gap over the dropped window's bounds, with the count. `dropped_flow_records` still counts as live health.
- **Shipping.** The reporter takes the held gaps onto the first request of each window's stream. If the stream fails it puts them back unmerged, so a delivery that partly landed repeats them exactly; delivery is at least once, as for records. A window that closes empty is still queued while gaps wait, so gaps never wait for traffic.
- **Bound.** Past its bound, the recorder now merges its two oldest gaps of the same kind and source. Precision is lost on the oldest evidence first, and the fact of a loss is never lost.

## Storage (ADR-0019, amended 2026-10-04)

- **Table.** Migration `00008_flow_gaps.sql` creates `flow_gaps`: workload (from the credential), kind, source, `gap_from`/`gap_to`, `lost_count` (NULL when unknown), `received_at`, and `region_id` reserved. It is unique on (workload, kind, source, from, to), so a repeated delivery is stored once. The same migration adds `workloads.source_overruns`.
- **Indexes.** (workload, gap_to) serves the read; gap_to serves retention.
- **Ingest.** Each gap is validated on its own; a malformed one is skipped and counted, like records, and at most 4,096 are accepted per request. Gaps are written in the window's transaction.
- **Retention.** Gaps are deleted in the same locked batches as windows, once they *ended* before the horizon, so a gap is kept at least as long as any window it describes.

## The gaps read

- **Named statement.** `ListFlowGaps` returns the gaps of a workload set (one workload, a label scope resolved now, or every workload) intersecting `[from, to)`. An instantaneous gap counts when its instant lies in the range. Newest first, bounded.
- **Surface.** `GET /api/v1/flows/gaps` takes the rollup's `from`/`to`/`workload`/`label` plus `limit` (default 500, at most 5,000) and returns `truncated`.
- **CLI.** `innerwall flows gaps` calls the same read-model function (ADR-0021).
- **Health.** `health.source_overruns` is added to workload health. The spec states both. `ui/src/api/generated.ts` is regenerated; under the standing fallout rule, the test fixture gains the new required field.
