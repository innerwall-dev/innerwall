One PR rather than two: this session may push to one branch only. The commits are in the order two PRs would have taken, and each stands on its own:

1. **Generated types swap** (carried): `ui/src/api/generated.ts` is generated from `api/openapi.yaml` and committed; the hand-written `types.ts` is gone; `ui/src/api/schema.ts` is aliases into the generated file and restates no field. `make console-api` regenerates; `scripts/check-drift.sh` runs it beside `proto sqlc` and fails on a diff, and the CI drift job installs the console's pinned dependencies to do so. Verified: a spec edit without regeneration fails the check. Problem types the console branches on are checked against the spec's closed set at compile time.
2. **Login composites** (carried): all four recaptured with both themes in the same interaction state (password typed; refusals after the same submit; clock held so the throttle countdown matches).

4. **Workload detail**: rail, status card (degraded is the hero), resend snapshot, inbound flows, listening services, rendered policy.

## Escalations (maintainer calls)

Decided in session (maintainer answers):
- **Fleet counts**: omit rather than walk every page. A totals field on the list (or a count read) is the endpoint ask for a later session.
- **Rule names** (conflict 1): the design names rules; authored rules have an id and a description only. Shown as description + short id until settled.
- **Peer kind drift** (conflict 2): the server emits `peer.kind` as `workload | group | address`, `api/openapi.yaml` (and so `generated.ts`) says `unknown | workload | address_group`. Reported only; the console reads the id fields and does not depend on `kind`. A follow-up decides which side is right.

Open, for a later endpoint session (the gaps above): fleet totals; the enrolling token on the workload; apply-failure and last-ack instants; per-flow policy version; interface names on addresses; a matching-scopes read for a label set; an earlier rendered version or its diff; the agent gateway address (and a served installer) for the enroll command.

Design has no shot for, and the console composes from its vocabulary: the change-mode dialog (the prototype's button has no handler), the revocation confirmation, non-degraded status cards, resend-snapshot placement, and the loading, error, and filtered-empty states.
