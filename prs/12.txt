## Summary

The operator write paths and the API contract (ADR-0021 decision 5, ADR-0007 as amended). The first two commits would have been separate PRs: migration and domain, then handlers and spec. After them come a merge of `main` and one commit applying the maintainer rulings.

**Migration and domain** (`8585d38`)
- Migration 00005 adds `rules.created_at`/`updated_at`, backfilled from the owning ruleset per the M3.2 maintainer ruling. It also adds `mode_changes` and `mode_change_workloads`, which record each bulk mode change as the intent submitted and the set it resolved to (the recorded-intent rule).
- `internal/policy`: every update and delete is conditioned on the version the caller last read. The check happens inside the write, and a moved object is refused with its current version. Rule-level create, update, and delete go through the ruleset write. A rule keeps its `created_at` across an edit of its ruleset, and its `updated_at` and version move only when the rule itself changed. Admission now collects **every** finding with a stable rule name and a path, which also improves the CLI's output. `MatchWorkloads` is the one scope resolution that the read model, the preview, and the mode change all call.
- `internal/fleet`:
  - Label edits are versioned by content.
  - A bulk mode change resolves, records, flips by id, and renders in one transaction under the render lock. It refuses when the expected count does not match.
  - Selector preview.
  - A dry-run render over a read-only snapshot, diffed through the shared `internal/rendered` implementation, persisting nothing.
  - A derived state version, so a stale author is detectable.
- The CLI's `set-labels`, `set-mode`, `token list`, and `token revoke` now call these domain functions. Its authored writes pass the version they read.

**Handlers and contract** (`a29307f`)
- Authoring CRUD (rulesets, rules, services, address groups) in the CLI's document form, plus `GET/PUT /workloads/{id}/labels`.
- Error handling on writes:
  - If-Match is required on every update and delete: absent → 428, stale → 412 with `current_version`.
  - Validation → 400 with `errors: [{path, rule, message}]`.

- `POST /mode-changes` → `{mode_change_id, matched, desired_updated}`, an acknowledgment only. A count mismatch → 409 with `expected` and `matched`. Also `POST /selectors/preview` and `POST /policies/render-dryrun`.

**Maintainer rulings** (`bc1200c`)
1. Resend-snapshot is removed from `api/openapi.yaml`. The spec had no path for it, only a mention in "Deliberately absent", and that mention is gone. The endpoint follows in M3.3b.
2. **Provisioning-token listing hint.**
   - Migration 00005 adds a nullable `provisioning_tokens.token_prefix`, written at mint as `iw_` plus eight leading characters, the operator token's shape.
   - Tokens minted before it list `prefix: null` (a `-` in the CLI), and nothing is made up for them.
   - A dated ADR-0016 amendment records the additive hint and corrects decision 3 in place. This makes ADR-0021's mirroring claim true.
3. **Versions: this PR implements the monotonic integer column.** The earlier scheme failed the ruling's test: the store parsed the client's token back into an instant before comparing. Now:
   - `rulesets`, `rules`, `services`, and `address_groups` carry `version bigint`, starting at 1.
   - Every write advances the version by one inside its own statement and returns the new value.
   - The token is the integer's decimal form. It is compared byte-exact against `version::text` inside the conditional statement and never parsed, so `"01"`, `"+1"`, and `" 1"` do not match `"1"`. Tests cover this at the store, domain, and handler layers.
   - A rule's version is carried across a ruleset edit and advances only when the rule changed.
   - Label versions remain content digests compared as strings.
4. The spec-vs-routes test is unchanged.
