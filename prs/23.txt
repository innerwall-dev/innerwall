## Persist before apply (audit: ACK without persistence; Critical)
- **Before:** `nft.Store.Apply` ran the kernel transaction first and saved the policy after. If the save failed it only logged the error and returned nil, so the daemon still acked `APPLIED` (`store.go:141–149`, `daemon.go:376–393` at `04e3209`).
- **Now:** the store gives the rules their mark values, then writes the mark allocation and then the policy durably: temp file fsync'd, renamed into place, parent directory fsync'd (new `enforce.WriteDurable`). Only after that does the kernel transaction run.
  - `APPLIED` means both steps succeeded.
  - A persistence failure → `FAILED`, kernel untouched, store/file/last ACK still agree.
  - A kernel failure after persist → `FAILED` with the file one version ahead. This is benign under the desired-state model, and ADR-0020 now records it.
- The ACK enum is unchanged.
- **Records:** ADR-0020 decision 6 and its contradicting consequence are amended. ADR-0018's durability note is corrected. The ARCHITECTURE reconcile sentence follows.

## Stable mark allocation (audit: attribution corrupted across versions; Critical)
- A persistent allocator (`marks.bin`, next to `policy.bin`) gives each resolved rule a value. Rendering never renumbers.
- A freed value is not reused until all 65,534 have been handed out once. After that the value freed longest ago goes first, and a value the installed policy holds is never taken.
- Classification looks the mark up in the allocator, so a connection names the rule that admitted it.
- **Removed-rule attribution:** a connection whose rule has been removed is reported `ALLOWED` with the removed rule's own id, never another rule's id. The wire has no removed-rule enum value, and the ruling forbids proto changes for this, so the removed rule's id is the faithful representation. Ingest stores rule ids as given.
- A state directory written before this change has no allocation. It is seeded in canonical order, which is exactly the numbering its kernel ruleset already carries.
- The 65,534-rule cap is unchanged. **Records:** ADR-0020 decision 4 (and decision 3's wording) are amended.

## Open-window bound (Major)
- The aggregator now holds at most `--flow-window-keys` distinct keys. The default is 50,000, the same as the closed-window buffer.
- A new key past the cap is dropped; keys already held still fold in. At close the window records one evidence gap: a new kind, `window_overflow`, from the first drop to the close, with the count of dropped observations.
- No existing kind fit: `buffer_overflow` means closed windows lost while the control plane is unreachable.
- The new kind is carried end to end:
  - proto enum value 5, additive; buf reports no breaking change
  - ingest
  - **migration 00009**, which widens `flow_gaps`' kind check
  - read model, OpenAPI and the console label
- Sampling and disk buffering remain deferred. ADR-0011 is amended to say so in PR 3, as ruled.
- **Records:** ADR-0019 decision 5 and ADR-0015 get dated additive notes.

## Identity parser strictness (Minor)
- `identity.ParseURI` now refuses percent-encoded paths, and any UUID whose canonical lowercase form differs from the text. Only the formatter's exact output parses.
- The audit's two accepted cases are now permanent tests.
