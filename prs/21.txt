## Gap 1: dump at every subscribe

- **Order.** Every subscribe runs `Listen` first, then `Dump` on a second `ct.Conn`, because the listening socket is in multicast mode. Nothing can open between the two unseen.
- **Classification.** Dumped flows take the NEW path: the inbound filter, the protocol mapping, then `Classify(mark)`. Each counts `Connections = 1` with no bytes, first seen at the subscribe instant; the eventual DESTROY carries the whole byte total.
- **Dedupe.** Keyed by `Flow.ID`, in both orders:
  - a dumped flow already sighted by a NEW is skipped;
  - a NEW for a flow the dump already counted is skipped;
  - a flow that closes while the dump is in flight is never counted by the dump, whether it was sighted or not.
- **DESTROY (ruling 4).**
  - A connection already sighted (by a NEW or the dump): bytes only.
  - A connection never sighted: `Connections = 1`, "found at close".
  - After a truncated dump, an unsighted DESTROY also widens the open `dump_truncated` gap to that instant.
- **Counting semantics.** `connection_count` is "connections opened, or found live at subscription, in the window". This is stated in the conntrack package doc and the architecture overview. The `FlowRecord.connection_count` field comment goes in PR B, which already changes `proto/`. PR A leaves the contract untouched.
- **Bound (rulings 1 and 2).**
  - `--flow-dump-max`, default `DefaultBufferRecords` (50,000), caps the dump entries processed. Entries past it are skipped and recorded as a `dump_truncated` gap with the count skipped.
  - The flag's help text and a code comment say the cap bounds processing, not the dump's peak memory. A dump loop of the source's own is recorded as the backlog path. The library and its pinned version are unchanged.
  - The same figure bounds the set of flow ids a subscription tracks. If a host exceeds it (logged once), a connection the set couldn't hold may be counted again at its close.

### Edge case settled: live flows marked WOULD_BLOCK

The rule holds. The would-block mark is written only by the terminal simulation rule, and that same rule logs the packet to nflog (`render.go`: `log … ct mark set … WouldBlockMark`). A connection older than the ruleset carries no mark in the agent's region, so `Classify` reads it as OBSERVED (`store.go`). A dumped flow marked WOULD_BLOCK was therefore logged when it was marked. The dump skips it, exactly as a NEW is skipped, and its DESTROY stays bytes-only. If nflog was down at the moment it was marked, that loss is nflog's own recorded gap.

## Gap 2: overruns, restarts, backoff

- **conntrack.** `ENOBUFS` (`errors.Is(err, unix.ENOBUFS)`, through the library's wrapping) ends the subscription, not `Run`. The source:
  - counts the overrun;
  - opens a `source_overrun` gap from the last event read;
  - resubscribes and re-dumps at once, with no backoff;
  - closes the gap at the new listen.
- **nflog parity.**
  - The library's receive loop keeps the socket bound after an error when the error func returns 0. So the log source counts the overrun, records the gap from the last event to the report, and reads on in place. Closing and reopening the socket would only widen the hole.
  - Sizing, never setting `NETLINK_NO_ENOBUFS`, restart gaps, and the backoff reset are the same as conntrack's.
- **Fatal errors.** These keep the backoff. A source that records gaps gets a `source_restart` gap opened at the failure and closed at its next successful subscribe, so a run of failed restarts is one interval.
- **Backoff reset.** `attempt` starts over after a run that stayed up longer than the backoff cap.
- **Socket sizing.** `--flow-netlink-buffer`, default 4 MiB, applied at every subscribe. In-session check of the FORCE variant: in the pinned `mdlayher/socket` v0.5.1, `SetReadBuffer` tries `SO_RCVBUFFORCE` and falls back to `SO_RCVBUF`. It is reached through `ct.Conn.SetReadBuffer` and `nflog.Con.SetReadBuffer`.
- **`NETLINK_NO_ENOBUFS`** is never set. A comment at each socket says why: it would hide the loss, not prevent it.
- **Bounds.** The gap recorder holds at most 1,024 gaps. Past that it merges gaps instead of dropping them, so the bound costs precision and never the fact that a loss happened (ADR-0011).
