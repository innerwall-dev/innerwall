## Login throttle (audit 2 #14)
- **Before:** `internal/api/throttle.go` claimed a 4,096-source bound, but at the bound it only dropped expired windows. So while every window was still running, each new source was admitted and the table grew without limit, with a full map scan per arrival.
- **Now:** windows sit in a list ordered by start time. A new source at the bound drops the oldest window, expired or not, so the table never exceeds 4,096 sources and each attempt costs constant work.
- **Caveat, kept accurate:** the brake is per process and bounded. A guesser rotating through more than 4,096 addresses within one window resets its own oldest windows. ADR-0021's "the login throttle protects one process" still holds.
- **Tests:** `TestThrottleBoundsSourcesWithinAWindow` is the audit's 5,000-sources-in-one-window case. `TestThrottleEvictsElapsedBeforeLive` covers eviction order.

## Third-party licenses in the built console (audit 2 #12)
- **Before:** the production build emitted six font files and no license text. The fonts' own metadata carries only a URL, and the font license requires the full text with every copy.
- **Now:** a Vite plugin (`ui/scripts/notices.ts`) writes these on every production build, read from the installed packages so it can't fall behind the lockfile:
  - `THIRD-PARTY-NOTICES.txt` at the console root: every production package with its version, license, and license text as shipped (MIT, ISC, BSD-3-Clause, 0BSD, Apache-2.0, OFL-1.1).
  - each font family's full license **beside the fonts** in `assets/`.
- Both are embedded in the binary. A Vitest suite checks the contents, and the console CI job fails a build that lacks the files.
- `THIRD-PARTY-NOTICES.md` at the repo root records the Apache-2.0-vs-bundled distinction. It avoids naming third-party companies in prose, under the current vocabulary rule. The README's license section follows in PR 4, as ruled.
