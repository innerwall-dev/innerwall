# ADR-0019: Single Go binary, stateless replicas, Postgres for state, key custody as the one exception, whole-estate rendering, and propagation by notification

**Status:** Accepted
**Supersedes:** ADR-0017

## Context

ADR-0017 restated the control-plane shape from ADR-0005 with the signing-key exception. Two of its bullets described the policy compiler and the routing of pushes before either existed: the compiler "recomputes only agents affected by a change", and a presence table maps agent to replica "so any replica can route pushes to the replica holding the stream". Implementing rendering and the sync stream (ADR-0018) produced code that does neither as written: version 1 re-renders every workload on every change and recovers per-workload versioning by diffing, and a render announces changed workloads on a Postgres notification channel so that every replica pushes to its own streams, with no table mapping agents to replicas. ADR-0017 is otherwise unchanged. This ADR restates it in full with those two bullets replaced, so that one record carries the control-plane shape and no Accepted ADR describes a compiler or a routing mechanism that does not exist.

## Decision

- One deployable **Go binary** containing internally separated services: API service, agent gateway, policy compiler, flow ingestion, signing authority. Boundaries are package-level interfaces, kept clean enough to split into processes later. The agent binary shares only the packages that define the wire contract, the identity representation, and the rendered-model algebra that is part of the contract's semantics (ADR-0018); control-plane packages never link into it.
- **All durable state in Postgres**, with one named exception below; replicas are stateless and interchangeable. HA = N replicas behind a load balancer + HA Postgres. Postgres is the availability story.
- **Signing-key custody is the exception.** The private key of the signing authority is operator-provisioned configuration, in the same class as the database connection string and the listener's TLS certificate, and never database state. With the file-backed authority (ADR-0020) the operator creates the authority directory once (`innerwall ca init`) and provisions it identically on every replica; every replica then signs with the same key and verifies against the same bundle, so interchangeability holds exactly as it does for any other identically configured replica. Two replicas that each generate their own authority are misconfigured, not two valid deployments. A backend that holds the key in a secrets manager or a hardware module removes even this from the replica's disk without changing the rule. Nothing else durable lives on a replica.
- **Changes propagate through Postgres, and each replica pushes to the streams it holds.** A render announces every workload whose version advanced on a Postgres notification channel, delivered when its transaction commits. Every replica listens and pushes to the live streams it holds, computing each delta from what that stream last received. Any replica can therefore accept any agent, a change made in any process reaches the right stream, and no replica needs to know which replica holds a stream. A presence table mapping agent to replica is deferred until a directed operation on one specific stream needs it; nothing does yet.
- **The policy compiler runs singly** under a Postgres advisory lock taken by every render transaction, in whichever process renders. Version 1 recomputes every workload's rendered policy on each change and advances a workload's version only when its rendered output changed (ADR-0018), so the blast radius of a version bump follows the blast radius of the edit even though the render does not. Narrowing the recomputation to the workloads a change can affect is an optimization behind the same versioning rule, not a change to it.
- Supported v1 deployment: single binary + single Postgres (co-located or adjacent), docker-compose. The distributed variants are documented seams, not shipped artifacts.

## Consequences

- Operations stay boring; a single artifact, a single database, and one configuration directory are the whole platform.
- Statelessness makes scaling and upgrades mechanical. Provisioning a new replica means copying configuration, the authority directory included, and nothing else; a replica holds stream state only, and a reconnect rebuilds it from a snapshot.
- Notifications and advisory locks tie coordination to Postgres, which is already the availability dependency. A replica whose listener drops reconciles every stream it holds against persisted state when the listener returns, so a lost announcement costs one reconciliation.
- Every change renders the whole estate. The cost is one transaction proportional to workloads times rules; the inverted label index recorded in ADR-0018 narrows it when a real estate demands, without changing what an agent sees.
- Internal boundaries must be defended in review; monoliths rot at exactly those seams. The agent binary's dependency set is part of that review.
- The signing key is the highest-value secret the control plane holds and it lives on the operator's terms, not the database's. Backup, rotation, and custody of the authority directory are operator responsibilities until an external key backend takes them over.
